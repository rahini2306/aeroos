## New work beyond the supplied syllabus

The syllabus explicitly covers scheduling, synchronization, deadlock avoidance/detection, memory policies, virtualization, RTOS and ROS. Rebranding those topics as “AI” would not add depth. The new feature is a finite-state **model-checking workflow** in C: breadth-first exploration of all enabled interleavings, state deduplication, invariant checking, shortest counterexamples, a runtime safety shield, exhaustive re-checking of shielded transitions, and an honest inconclusive result on search limits.

The shield uses classical maximum-claim safety; that part is not claimed as new. Formal model checking is a standard research/engineering technique outside the topics listed in the supplied syllabus, not an algorithm invented by this project. The project-specific contribution is connecting it to editable airport-service resource models and replayable evidence.

## Guarantees and exclusions

- A “verified” result means the finite acquisition-plan model was exhausted and no nonterminal dead-end was reachable.
- The checker does not prove the C implementation, real pthread code, the whole airport engine, fairness of the host, or physical flight safety.
- Search limits return inconclusive. Graph previews may be clipped independently of the complete exploration.
- The new native verifier has an independent Python transition-system oracle in tests, including 35 seeded models.
- User data is preserved. Tests use temporary SQLite databases.
- Responsive styles and focused browser checks do not amount to a full device/accessibility matrix. No ThreadSanitizer or exhaustive long-duration leak audit has been run.

See `docs/beyond-syllabus.md` for the viva defense and formal-model contract.
