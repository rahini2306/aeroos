# Viva preparation

1. **Why implement the algorithms in C?** It makes OS logic independently executable and testable, with explicit memory, resource ownership, and real POSIX primitives. Python is the integration layer and React is presentation.
2. **Why not make every flight a pthread?** Host scheduling would make airport results nondeterministic. A discrete integer boundary simulation allows fair policy comparisons and exact replay; threads are demonstrated separately.
3. **What is the PCB analogy?** Each flight has identity, arrival/burst/remaining service, base/effective priority, state, requested/allocated resources, memory, waiting/response/completion times, bypass count, and recorded history.
4. **What does a burst represent?** One educational non-preemptible airport service interval, or an abstract pausable task in CPU mode. It is not a complete physical flight trajectory.
5. **Can RR interrupt takeoff?** No. Airport mode rejects RR/SRTF/preemptive priority/MLFQ. Those run on abstract service tasks.
6. **How is preempted waiting calculated?** Add every unit interval spent READY/BLOCKED. For completed jobs, verify turnaround = burst + waiting. A single initial timestamp cannot capture multiple waits.
7. **Why can a shorter job start later than an emergency?** Emergency precedence is a configured common admission rule applied before the policy's normal ranking. Policy comparisons share it.
8. **What is HRRN?** Choose the largest `(waiting + burst) / burst` among eligible jobs at a non-preemptive dispatch.
9. **How are MLQ and MLFQ different?** MLQ keeps static priority bands; MLFQ moves CPU-consuming tasks down three queues with larger allotments.
10. **Does priority aging prove absence of starvation?** No. It improves priority according to accumulated ready wait in finite experiments. It is not a theorem about unbounded emergency arrivals or unavailable resources.
11. **What prevents airport deadlock?** Atomic all-or-nothing bundle admission prevents hold-and-wait. Partial allocations and outstanding requests are explored separately in Safety lab.
12. **What are the four conditions?** Mutual exclusion, hold-and-wait, no preemption, circular wait. A multi-instance graph cycle alone does not establish deadlock.
13. **How does detection differ from Banker?** Detection uses current outstanding requests. Banker uses maximum future claims to determine whether some completion order is guaranteed.
14. **Is unsafe the same as deadlocked?** No. Unsafe means no guaranteed completion sequence under maximum claims; processes may still complete without requesting their full claims.
15. **What happens to an unsafe tentative request?** Safe mode rolls back Available, Allocation, and Need exactly. Normal mode grants an otherwise valid available request and reports unsafe.
16. **How is the recovery victim chosen?** The user may specify its index; otherwise choose an affected process with the fewest allocated units. Terminate, release, and rerun reduction. Additional victims may be necessary.
17. **How do semaphores work on macOS?** Named POSIX semaphores use `sem_open`, immediate `sem_unlink`, and `sem_close`. The code does not rely on unavailable unnamed `sem_init` support.
18. **Why is the race demo safe C?** It uses atomic loads/stores and a barrier to force a logical lost update; there is no undefined data race on a plain integer.
19. **How is producer-consumer bounded?** Empty/full semaphores guard a sixteen-element circular queue, while a mutex guards queue indices and contents. Even thread counts pair producers/consumers, and all threads join.
20. **How is dining deadlock prevented?** Every worker acquires the smaller-indexed resource first, eliminating circular lock ordering.
21. **What is external fragmentation here?** Sum of free-hole sizes minus the largest free hole. Compaction packs live blocks to combine free space.
22. **Why is contiguous internal fragmentation zero?** These variable partitions allocate exactly the requested size. Paging uses optional process byte sizes to calculate last-page waste.
23. **What is a page fault versus replacement?** A fault is a missing page; an initial empty-frame fill is a fault without eviction. Replacement requires an occupied victim frame.
24. **Why can't Optimal be deployed online?** It needs the future reference string. It is an offline lower-bound benchmark.
25. **What makes replay exact?** It selects immutable boundary snapshots generated by C, including owners and waiting intervals. Backward navigation does not guess an inverse transition.
26. **Why don't thread traces replay deterministically?** They come from real host scheduling. Recorded traces can be inspected, but reexecuting pthreads can produce a different order.
27. **Is congestion analysis ML?** No. It uses a documented arrival/service fluid-queue heuristic and compares predictions to recorded outcomes.
28. **What is the model's biggest limitation?** A flight holds a complete resource bundle for its full service. Future work would model sequential phases and phase-specific claims, with much more complex resource dependencies.
29. **What makes a comparison fair?** Identical arrivals, bursts, priorities, emergency rules, quantum/aging assumptions, and service context. The arena fixes one abstract CPU for every policy.
30. **What has actually been tested?** See the raw test log and verification matrix. Do not describe unperformed load, phone, race-detector, or leak-audit checks as completed.
